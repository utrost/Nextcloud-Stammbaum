# Paged collections and targeted backlinks: alpha.28

This increment advances [#81](https://github.com/utrost/Nextcloud-Stammbaum/issues/81), [#83](https://github.com/utrost/Nextcloud-Stammbaum/issues/83), [#84](https://github.com/utrost/Nextcloud-Stammbaum/issues/84) and [#86](https://github.com/utrost/Nextcloud-Stammbaum/issues/86). It builds on the [alpha.27 acceptance record](integration-acceptance-alpha27.md) without changing the archived release specification or claiming broader parity.

Task-list and Calendar discovery now take a zero-based `page` and return no more than 50 current-account collections, `items` for writable choices, `readOnlyItems` for explicit read-only choices and `nextPage` when another page exists. The current account's collections are ordered by opaque URI before slicing; invalid pages fail validation. The browser checks VTODO/VEVENT support through authenticated same-origin DAV, and **Load more** retains the current form and selection. Unproven outward sharing remains **unknown**. A fictional Playwright fixture created 52 collections through Nextcloud's public `occ dav:create-calendar` command, verified a second page, keyboard selection at 320 pixels, another account's isolation, then force-deleted every fixture collection. Direct DAV creation hit Nextcloud's request rate limit during the first setup attempt; the test uses the public CLI solely for fixture setup and cleanup.

Task DESCRIPTION backlinks now point to the specific authorized person, source, medium or shared event. Calendar DESCRIPTION links for shared events open one authorized participant's timeline and the exact event. The app fetches each target through its ordinary authorization endpoint before showing its detail. An inaccessible shared-event ID in a forged hash produces no event card or title. The navigation has no genealogy write. Long iCalendar URLs are folded according to the format; the browser tests unfold them before asserting target IDs.

The alpha.28 runtime archive `build/stammbaum-0.1.0-alpha.28.tar.gz` has SHA-256 `3352ee25a0115d98badb1afdf23a738048fc1d2209a7c62da89c572a24e4074c`. The isolated 52-collection Playwright journey passed; all three expanded integration journeys passed after adding source, medium and event backlink assertions, including the forged hidden-event URL. A separate five-account journey passed for all four tree roles, export-grant changes, administrator isolation, living and management-only inclusion, hidden shared-event dependencies and unchanged tree revisions during review. Task and Calendar iCalendar unit scripts, PHP syntax, source/build, format, package and documentation checks passed. Full-suite CI and Alice deployment are reported with the PR rather than inferred from these focused checks.

The Nextcloud 34 public calendar manager still cannot establish outward sharing or component support server-side, so the UI's DAV check and unknown-audience warning remain necessary. The non-atomic Tasks reservation/DAV write boundary and the broader shared/read-only collection, recovery, log/cache and EN/DE acceptance matrix remain in the four issues above.
