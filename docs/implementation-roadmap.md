# Implementation roadmap

## Product digest and authority

Stammbaum is a closed research workspace: a tree is both a genealogy dataset and an access boundary. People are not accounts. Each tree independently grants viewer, editor, manager or owner access; viewers/editors require an additional export grant. An installation administrator has no automatic genealogy access.

Unknown values remain unknown. Names, dates, explicit parentage and partnerships must not be invented from layout, sex or other contextual information. Sources describe material; reusable citations target assertions with independent evidence effects. Historical assessment and display preference are separate. Shared records require access to all affected dependencies, including historical private assertions.

Original imports/media are immutable evidence; current edited research is a separate projection. GEDCOM export, original-file download, portable archive and operational backup have different guarantees. Reviewed import activates atomically into an empty tree. Export reflects authorized current research and expires or becomes invalid when the tree/access state changes. Concurrent edits retain drafts for deliberate reconciliation.

The primary handoff is [release 0.15, document 1.0](intial-spec/current-product-specification.html), dated 6 November 2026, archived from commit `37040733982e5a2b3dacfb48f07ef3ba7a33f05f`. Its [immutable GitHub text](https://github.com/utrost/Nextcloud-Stammbaum/blob/37040733982e5a2b3dacfb48f07ef3ba7a33f05f/current-product-specification.txt) keeps published issue references usable before these documentation changes are committed.

The handoff links the [original functional baseline](https://github.com/utrost/Stammbaum/blob/d5809c3470fe53604ffd4307428c3a68053e77b5/docs/functional-specification-v1.md), [decision register](https://github.com/utrost/Stammbaum/blob/d5809c3470fe53604ffd4307428c3a68053e77b5/docs/decisions.md), cumulative [M2a](https://github.com/utrost/Stammbaum/blob/d5809c3470fe53604ffd4307428c3a68053e77b5/docs/migration/m2a-profile.md)/[M2b](https://github.com/utrost/Stammbaum/blob/d5809c3470fe53604ffd4307428c3a68053e77b5/docs/migration/m2b-profile.md)/[M2c](https://github.com/utrost/Stammbaum/blob/d5809c3470fe53604ffd4307428c3a68053e77b5/docs/migration/m2c-profile.md)/[M2d](https://github.com/utrost/Stammbaum/blob/d5809c3470fe53604ffd4307428c3a68053e77b5/docs/migration/m2d-profile.md) exchange profiles and [integration contract](https://github.com/utrost/Stammbaum/blob/d5809c3470fe53604ffd4307428c3a68053e77b5/docs/api/integration.md) at source revision `d5809c3470fe53604ffd4307428c3a68053e77b5`. Later profile amendments override earlier gaps only where explicitly described. Two source ADRs have the number ADR-015; references distinguish locale/home from integration access.

The release snapshot defines parity, not full original-product completion. Original K/core, A/expansion and X/optional classifications remain intact for deferred work. Screenshots and Appendix A describe expected behavior, not execution evidence. Native test results are recorded in [iteration 1](iteration-01.md) and [iteration 2](iteration-02.md); they do not certify complete parity.

## Native Nextcloud adaptations

Use the existing development environment and [Library/Relate reference practices](development.md). The user authorizes the Alice development system without a pre-deployment backup requirement. Product backup/recovery remains a separate feature; it does not gate ordinary development deployment. The initial development target is Nextcloud 34, with broader compatibility determined and tested in F01.

[F01 · #2](https://github.com/utrost/Nextcloud-Stammbaum/issues/2) records the compatibility matrix and exact adaptation contracts before implementation. The source Java stack, standalone account system and deployment choices are not requirements for this app.

| Concern | Target and decision boundary | Issues |
| --- | --- | --- |
| Identity and operators | Use stable Nextcloud user identity, authentication, provisioning and account administration. Keep people separate and tree ACLs independent. Define disable/delete/reactivate behavior and last-owner handling, including host-forced changes. | [F01 · #2](https://github.com/utrost/Nextcloud-Stammbaum/issues/2), [A01 · #8](https://github.com/utrost/Nextcloud-Stammbaum/issues/8), [A03 · #10](https://github.com/utrost/Nextcloud-Stammbaum/issues/10) |
| Invitations | Single-use 48-hour tree invitations require explicit authenticated acceptance. New host accounts follow Nextcloud provisioning; copied links do not grant anonymous access or send automatic mail. | [A05 · #12](https://github.com/utrost/Nextcloud-Stammbaum/issues/12) |
| Sessions and recovery | Host authentication/session/password recovery replaces standalone setup, restart logout and 30-minute password-reset workflow. Do not terminate unrelated host sessions. Document app-credential invalidation hooks or fail-closed alternatives. | [F01 · #2](https://github.com/utrost/Nextcloud-Stammbaum/issues/2), [A01 · #8](https://github.com/utrost/Nextcloud-Stammbaum/issues/8), [I01 · #40](https://github.com/utrost/Nextcloud-Stammbaum/issues/40), [I06 · #45](https://github.com/utrost/Nextcloud-Stammbaum/issues/45) |

Preserve authored content and drafts; device timezone is independent of research dates. | [F01 · #2](https://github.com/utrost/Nextcloud-Stammbaum/issues/2), [I04 · #43](https://github.com/utrost/Nextcloud-Stammbaum/issues/43) |
| Private files | Store immutable opaque originals under app control with all-target ACL checks; ordinary Nextcloud file sharing cannot bypass genealogy restrictions. Track app-wide logical quotas. | [F04 · #5](https://github.com/utrost/Nextcloud-Stammbaum/issues/5), [M01 · #32](https://github.com/utrost/Nextcloud-Stammbaum/issues/32), [M02 · #33](https://github.com/utrost/Nextcloud-Stammbaum/issues/33) |
| Jobs | Durable state plus Nextcloud background execution with initiator identity, version checks, cancellation and atomic publication. Host cron concurrency cannot bypass authority. | [F06 · #7](https://github.com/utrost/Nextcloud-Stammbaum/issues/7), [M06 · #37](https://github.com/utrost/Nextcloud-Stammbaum/issues/37), [M08 · #39](https://github.com/utrost/Nextcloud-Stammbaum/issues/39) |
| Tools | App-scoped selected-tree grants intersect current rights. Broad host app passwords alone do not implement these restrictions. Membership generations prevent old grants reviving. | [I01 · #40](https://github.com/utrost/Nextcloud-Stammbaum/issues/40), [I02 · #41](https://github.com/utrost/Nextcloud-Stammbaum/issues/41) |
| Recovery | Back up app data/originals/signing material consistently with host procedures. Explicit restore invalidation prevents old grants and links becoming active from restored snapshots. | [I06 · #45](https://github.com/utrost/Nextcloud-Stammbaum/issues/45) |

The native browser API, initial research schema and a bounded reviewed import are implemented; see [iteration 1](iteration-01.md), [iteration 2](iteration-02.md), the [import profile](gedcom-import-profile.md) and [architecture](architecture.md). The scoped external-tool API remains unimplemented. The issues define the complete required service contracts: stable tree-scoped identities, versioned mutations/idempotency, typed historical dates and assertions, staged import bindings, current-state export snapshots, scoped credentials, and versioned minimal webhook payloads. Implementation publishes native routes and schemas through [I02 · #41](https://github.com/utrost/Nextcloud-Stammbaum/issues/41); source route prefixes are not a drop-in compatibility promise.

Each published issue includes source references, acceptance criteria, failure/authorization tests, scope exclusions and actual issue dependencies. [backlog.json](backlog.json) retains their reviewable bodies and identifiers. Milestones group work; dependency links determine ordering and no dates are implied.

Build native compatibility/scaffold/schema first; shared authorization, mutation, storage and job foundations precede domain workflows. Genealogy/evidence supports workspace and exchange. Integration, recovery and acceptance complete parity. Deferred work remains outside parity milestones.
