# Alpha.30 media and export closure

This iteration addresses [#39](https://github.com/utrost/Nextcloud-Stammbaum/issues/39), [#74](https://github.com/utrost/Nextcloud-Stammbaum/issues/74) and [#69](https://github.com/utrost/Nextcloud-Stammbaum/issues/69). It preserves the archived release-0.15 handoff in `docs/intial-spec/`. ZIP package candidate review (#34) and the cumulative M2d semantic mapping (#36) remain separate parity work.

## Current behavior

- Export preview admits exactly 50,000 included current objects and rejects the next object before a job is created. The worker's final state/authority check shares the serialized write guard with cancellation. A cancellation before that checkpoint cannot publish or download the generated GEDCOM, report or ZIP. The existing 2,000-person, 64 MiB media, hourly/queue, 24-hour expiry and permanent invalidation contracts remain in force.
- Every imported GEDCOM `FILE` entry remains visible as its original, immutable wording. A tree editor can review that exact entry, select a currently readable JPEG/PNG/PDF from Nextcloud Files, inspect the filename/type/size/tree visibility and confirm one unchanged private copy. Selection uses the existing server-side byte validation, source ETag/permission checks, quota reservation and idempotent upload path. The source file is never modified and later source edits, deletion or share changes do not alter the copy.
- The reference match is committed with media publication in `stb_media_matches` migration 000122. The record's current availability is derived from authorized active matches; `original_json`, the preserved GEDCOM nodes and the original reference string are unchanged. Trash immediately makes the match unavailable. Restoring a valid medium makes it available again. Deleting a participant severs both the match and any shared-event media attachment so restoring the person cannot recreate either link. A hidden matched copy does not reveal its media ID or status to ordinary members.
- JPEG preview generation reads a bounded EXIF orientation tag and applies orientations 1–8 once to derived PNGs. Absent, unsupported and malformed orientation data falls back to raw orientation. Preview identity `raster-v2` prevents reuse of old raw-orientation cache entries. New crop rectangles use normalized oriented coordinates; legacy rectangles without a coordinate-space marker are converted on read, preserving the selected raw pixels. No original is rewritten and no original EXIF/GPS is copied into a preview.

## Interfaces and operator notes

`GET /trees/{tree}/media/reference/{record}` returns the authorized original FILE entries, current record revision and visible match state. `POST /trees/{tree}/media/import-file` accepts `referenceRecordId`, `referenceField` and `referenceRevision` alongside the existing selected file ID/ETag and idempotency key. The server verifies the immutable import mapping, every original/current participant, tree role, record revision, source read authority and required media visibility. The route does not accept a filesystem path, public share URL or remote URL for the copy itself. Restricted original references require manager-only media.

The private copy consumes the installation original-media quota and remains governed by the tree/media permissions even if the Nextcloud Files source is later unshared. A matched copy in trash can be restored by management using the normal media-trash workflow; a removed person match requires a new explicit review after restoration. Existing ZIP-package matching remains unavailable. The export review warns that an output ZIP can exceed the 32 MiB/100-entry input package limits, requiring media to be split for transfer. Exported GEDCOM is a current-state exchange format, not a lossless app backup.
