# Nextcloud Contacts linking (alpha.24)

Stammbaum can link a genealogy person to a card in an address book readable by the acting Nextcloud account. The link is account-private and stores only the book key, card UID/URI, a content fingerprint and its own review state. It does not infer identity from a matching name or email. Search is bounded and a selected card is re-read before linking. Links do not change the tree revision. A missing, deleted or inaccessible card is shown as unavailable without substituting a similarly named card. Unlinking leaves the card and any prior genealogy copies intact.

A manager or owner can compare the current card's email, phone or postal address with saved genealogy values, then append or replace one management-only contact record through the ordinary versioned record/history pipeline. The user must confirm that a copied field remains in the tree independently after the card changes or access is lost. Cards and copied records are never synchronized automatically. Birthdays and photos are not copied; a read-only birthday-present signal can help avoid duplicate Calendar entries.

The initial #85 wording allowed an editor to copy. Existing confidential-contact rule #24 requires **manager or owner** authority for all genealogy contact records, and the integration preserves that stricter rule. Editors and viewers can create their own private links but cannot copy a field into a management-only record. This is an intentional authorization adaptation, not a change to the archived specification.

The adapter uses Nextcloud's public Contacts manager and address-book interfaces on Nextcloud 34, with Contacts 8.9.3 pinned in the disposable CI fixture. No direct Contacts database access, DAV credentials or private card text are persisted in the link table. An account deletion/recreation clears its links; member revision changes invalidate older links. Optional Contacts absence disables only this workspace. The core genealogy app has no hard Contacts dependency.

The current field-copy review has a five-minute lifetime and binds the current card fingerprint, person/member/tree revisions and target record revision. A remote card write exactly between the final re-read and genealogy save cannot be made atomic across Contacts and Stammbaum; a later refresh marks the link changed and never silently overwrites the saved copy. This is a residual cross-app race for #86's broader verification.

Verification uses fictional cards and people. Focused browser tests cover private linking, no-export members, foreign books, a shared read-only book and its revoked share, hidden people, same-name and multiple selected cards, changed/deleted cards, editor denial for confidential copy, stale replacement review, versioned copy, unlink and English/German keyboard/mobile review. A disposable-only check disables Contacts and confirms the genealogy API remains usable. The full suite, Alice deployment and CI evidence are recorded with the release/PR rather than inferred from this document.
