# Export reliability and native reimport — alpha.21

The alpha.20 export could write a family NOTE and a source NOTE that the native importer correctly rejected as unsupported fields. It also emitted a separate spouse-slot family for an explicit partner connection, but the importer deliberately does not infer a partnership from those slots. An export of the fictional family fixture therefore lost its partner edge on reimport.

Alpha.21 writes a source description with standard SOUR/TEXT and omits the unsupported family note. Export profile `nc-gedcom-551-export-alpha2` writes `1 _STB_PARTNER Y` only for an explicit current partner edge. Import profile `nc-gedcom-551-alpha4` accepts that exact marker on a FAM with two adults and no MARR/DIV; invalid or ambiguous markers block activation. The marker does not create a marriage event or infer a partnership from co-parenthood. Other GEDCOM software may ignore it, so the export fidelity report warns that partner meaning may be lost. Full family-context grouping and broad consumer interoperability remain open in #36 and #38.
