# Alpha.23: first Nextcloud Tasks journey

This iteration implements a small part of [the optional Nextcloud integration concept](nextcloud-integration-concept.md) and issues #81–#83. It does not close those issues or change the release-0.15 parity baseline. The exact verified development target is Nextcloud 34.0.4, Tasks 0.18.1 and the built-in DAV backend 1.40.0. CI installs the official Tasks 0.18.1 release only into its disposable fictional fixture and checks the pinned SHA-256; Alice already has Tasks 0.18.1.

## Delivered journey

Alpha.25 tightened the outbound privacy default: a management-only person now requires a separate explicit inclusion choice, even for a manager or owner who may read that person.

An account with export authority can open a person and choose **Create research task**. The app discovers writable calendars through Nextcloud's public calendar manager, then uses the signed-in account's same-origin CalDAV session to identify collections supporting VTODO. The user enters a title, optional note and due date, reviews the copied content and separate task-list audience, then confirms. Living or unknown-status people require a separate explicit inclusion choice. A management-only person is available only to a manager/owner. The task includes a route back to that person; opening the route rechecks current tree access.

The server creates a private operation row with a random UUID and source/membership revisions. It stores a payload hash for retry matching, but no task title, note or due date. A retry must supply the same current review to reconstruct the task. The browser submits one VTODO at a deterministic object name with `If-None-Match: *`. On success the server verifies the VTODO UID through the public calendar search interface and marks the link as created. Repeating the same confirmation reuses the operation ID; the conditional DAV write prevents overwriting an existing object. A failed verification is shown as uncertain rather than as a successful task. Review data expires after five minutes; new task operations are limited to 20 per account per hour. An expired pending operation keeps only its opaque identity for investigation.

Links are per account, not shared with the tree. The app does not grant access to task collections, alter genealogy facts or change tree revisions for task operations. The private registry is removed on account deletion/recreation. Password change or account disable invalidates pending operations; later membership changes prevent older operations from being completed or shown as active. The destination Tasks app and any devices it syncs with retain their own copies and permissions.

## Architecture boundary

Nextcloud 34's public calendar manager supports discovery, permission checks and search, but does not expose a general VTODO write method. The first slice therefore performs the DAV PUT in the authenticated browser session. The server authorizes and constructs the payload immediately before returning it. A tree permission change between that response and the browser's DAV PUT cannot be made atomic across the two apps; the post-write check refuses to publish a valid Stammbaum link after a source or authority change, but it cannot recall the external copy. The user is told about this disclosure boundary. A future server-mediated adapter or stronger protocol flow is needed to eliminate this #81 boundary.

Alpha.26 subsequently added account-incarnation receipts, bounded cleanup, a personal Connections view, local unlink and conditional removal of newly created unchanged tasks; see [the connection lifecycle](connections-iteration.md). **Open Tasks** goes to the Tasks app rather than relying on an unverified item URL.

## Alpha.27 extension

The same reviewed task action is now available from a source, shared event or image/PDF medium, as well as a person. The task contains the user's bounded title and instruction plus a backlink; original media and unreviewed evidence fields are never copied. A shared event requires every participant to remain readable. Media checks assignments, named people and any linked event; a name without a tree person is treated as unknown living status. A trashed medium or hidden shared dependency cannot be used to confirm an old review. Typed source identity and a dependency digest are stored with the private receipt. Source or dependency edits mark the connection as changed without overwriting the task.

The editor offers a date-only due date and iCalendar priority 1 (high), 5 (normal), 9 (low) or 0 (unspecified). Date-only is deliberate: it does not silently interpret a historical date or invent a timezone. A foreground refresh reads only the current VTODO completion state through Nextcloud's public calendar search, showing completed, open or unknown; a deleted, moved or unreadable destination is shown as changed/unavailable, never as a completed task. Task text remains in Tasks. The personal Connections view shows the same completion result when the source is still authorized.

Collection discovery now reports `shared-with-me` when Nextcloud exposes that fact; all other sharing is honestly `unknown`, because this public API cannot prove that an owned collection has not been shared outward. Read-only collections are reported separately and cannot be selected for creation. The authenticated browser checks VTODO support through a bounded same-origin DAV `PROPFIND` before displaying a task list. The server checks current creation permission but cannot independently inspect supported components through the public `ICalendar` interface. A direct API review of a VEVENT-only collection therefore does not promise that a DAV write will succeed; DAV rejects the incompatible write. Every destination still requires explicit audience acknowledgement. There is no reliable private-only destination default in this API.

The cross-app revocation window remains. An isolated browser test deliberately revokes export permission after a task reservation and before the DAV write. Tasks accepts the already issued VTODO, while Stammbaum refuses completion and retains an opaque permanently invalid link. The external copy must be handled in Tasks. This is a product limit to assess before closing #81, even though the local authorization and failure state are tested.

## Verification

The focused Playwright test uses a fictional person and real VTODO collection. It checks the review at 1440, 390 and 320 px, keyboard confirmation, the persisted task UID/backlink, conditional duplicate rejection, no tree revision change, denied viewer export, living/unknown default, idempotent reservation and stale person edits. The entire browser suite, CI and Alice smoke results will be recorded after execution; documentation checks alone do not certify this journey.
